# Huffman File Compression Utility

A lossless file compression and decompression utility built in **C++** using the **Huffman Coding algorithm**.

**Authors:** Shivram Parkhi and Ishaan Jog

The project implements Huffman coding from scratch, including frequency analysis, Huffman tree construction, binary encoding, bit packing, and reconstruction of the original file during decompression.

## Features

* Lossless file compression using Huffman Coding
* Decompression of `.huff` files
* Supports text and binary files
* Binary file handling using C++ file streams
* Bit-level packing of Huffman codes
* Stores the frequency table required for decompression
* Handles padding bits using the encoded bit length
* Displays compression statistics such as:

  * Original file size
  * Compressed file size
  * Space saved
  * Compression percentage

## How It Works

### Compression

1. The input file is read in binary mode.
2. The frequency of every unique byte is calculated.
3. A min-priority queue is created using the byte frequencies.
4. The Huffman tree is constructed by repeatedly combining the two nodes with the lowest frequencies.
5. Huffman codes are generated by traversing the tree:

   * Left edge → `0`
   * Right edge → `1`
6. The original file is encoded using the generated Huffman codes.
7. The encoded bits are packed into bytes and written to the compressed file.
8. Metadata required for decompression is stored along with the compressed data.

### Decompression

1. The compressed file header is read.
2. The stored frequency table is reconstructed.
3. The Huffman tree is rebuilt using the frequencies.
4. The compressed bytes are read bit by bit.
5. Each bit is used to traverse the Huffman tree.
6. When a leaf node is reached, the corresponding byte is written to the output file.
7. Decoding continues until the stored encoded bit length is reached.

## Compressed File Format

The generated `.huff` file follows this structure:

```text
+----------------------------------+
| Number of unique bytes           |
+----------------------------------+
| Byte 1 | Frequency 1             |
| Byte 2 | Frequency 2             |
|   ...                            |
| Byte N | Frequency N             |
+----------------------------------+
| Encoded bit length               |
+----------------------------------+
| Huffman encoded binary data      |
+----------------------------------+
```

The frequency table allows the decompressor to reconstruct the Huffman tree, while the encoded bit length prevents padding bits in the final byte from being interpreted as actual compressed data.

## Compilation

The project requires a C++ compiler with C++17 support.

Using `g++`:

```bash
g++ main.cpp compression.cpp decompression.cpp -o huffman -std=c++17
```

### Run

On Windows:

```bash
huffman.exe
```

On Linux/macOS:

```bash
./huffman
```

## Usage

After running the program, choose whether you want to compress or decompress a file.

```text
===== Huffman File Compression Utility =====

1. Compress File
2. Decompress File
3. Exit
```

### Compression

Provide the path of the file you want to compress.

The program generates a `.huff` file containing the compressed data and the metadata necessary for decompression.

### Decompression

Provide the path of a `.huff` file.

The program reconstructs the Huffman tree and restores the original file contents.

## Example Compression Result

Huffman coding works particularly well on files where certain byte values occur much more frequently than others.

For example, during testing on a highly repetitive text file:

```text
Original file size   : 104,857,851 bytes
Compressed file size : 59,050,787 bytes
Space saved          : 45,807,064 bytes
Compression          : ~43.68%
```

Compression results vary significantly depending on the input file.

Files that already use compression, such as JPEG images, MP4 videos, ZIP archives, and many PDFs, may show little reduction in size or may even become slightly larger because of the additional Huffman metadata.

## Limitations

* Huffman coding alone may not significantly reduce files that are already compressed.
* The compressed format is currently specific to this implementation.
* The current file format stores the complete frequency table, which introduces some metadata overhead.
* Compression efficiency depends heavily on the frequency distribution of bytes in the input file.

## Future Improvements
